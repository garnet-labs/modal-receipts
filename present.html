What a customer adds

sb = modal.Sandbox.create("sleep", "infinity", app=app, image=image, runtime="vm", memory=3072,
    experimental_options={"proxy_traffic_via_sidecar": "garnet", "vm_sidecar_memory_reserve_mib": 1024})
sb._experimental_sidecars.create("python", "-u", "/recorder.py", name="garnet", image=garnet_image,
    experimental_memory_reserve_consume_mib=512, outbound_domain_allowlist=[...])  # optional

Modal relays every TCP/443 connection from the sandbox to the Sidecar as raw TCP. The Sidecar reads the host name from the TLS ClientHello (SNI), passes the bytes through unchanged, and writes one line per connection. Nothing decrypted, nothing installed in the sandbox image. Zero engineering to try, one runtime flag to ship.

Step 5: a revised policy constrains the next run

The program's demonstration: an agent executes a task; the ordinary agent trace misses a consequential subprocess or outbound connection; Garnet captures it; the verification result changes a review decision; a revised policy constrains the next run. On Modal, the last step is Modal's own control.

  • Union of the 30 runs' hosts (10 hosts) set as the Sidecar's outbound_domain_allowlist; 10 installs rerun: 10 of 10 exit 0, 10 of 10 agree. Each receipt carries sidecar.policy: the list, its source ("evidence-derived: union over 30 real runs") and who enforces it (Modal, on SNI).
  • curl https://example.com from the sandbox, a host outside the union constructed: recorded as refused_by_policy with policy_source: sidecar.outbound_domain_allowlist (evidence-derived …); upstream TCP opened, 517 B sent, 0 B returned, curl rc=35. Same step with no allowlist: relayed, 200. A refused host is visible in the receipt, not silent.
  • Main container outbound_cidr_allowlist=[] next to the relay: installs still pass; curl http://example.com:80 constructed times out, refused by Modal before it reaches anything. In that shape all permitted egress except DNS goes through the Sidecar (tested for port 80).

What this is not

  • Not more than Modal sees host-side. Modal relays the bytes; the Sidecar writes them down for the customer, in the customer's account, in the same receipt format as a GitHub Actions job.
  • Not TLS inspection and not the original destination: hosts are the SNI the client sent (SO_ORIGINAL_DST empty in 64 of 64 runs, as documented).
  • Not DNS, other ports, UDP, or the Sidecar's own traffic. Every receipt says so.
  • The in-VM half is optional, Linux audit today; the production shape is a cgroup-BPF connect hook + proc connector, which the guest kernel already supports.
